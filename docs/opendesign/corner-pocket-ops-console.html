What this is. Every frame below is the markup the shipped console renders, taken from the same code the browser runs (the app is booted in the test suite's own sandbox and each screen is called directly). Nothing here is redrawn: if a frame looks wrong, the app looks wrong. The stylesheet is inlined from annotator/ops.css with #ops-shell renamed to .od-shell, so the phone rules still fire when a frame's width drops below 750 px — narrow this window to check them.
How to annotate. Edit anything in place, or draw on it; then the repo picks it up: ~/projects/opendesign-sync/bin/odsync pull corner-pocket mirrors this project into .od-sync/design/ with DESIGN-HANDOFF.md, I implement it, and odsync push corner-pocket puts the built result back beside the design.
Not here: the app's data (every list is the test fixture), the live Vision stage's pixels (the adapter fills that surface at runtime), and the server-side states (offline, 409, 503), which are behaviour rather than layout.
